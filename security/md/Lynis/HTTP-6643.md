# HTTP-6643 ([retour](../lynis.md))

ModSecurity est un pare-feu applicatif permettant de filtrer les requêtes HTTP. Il fonctionne, comme tout pare-feu, sur la base de règles que l'on pourra définir.

Par défaut, il n'y a aucune règle. Nous pouvons soit les définir, soit installer des règles préconçues. Pour ce dernier cas, nous installerons OWASP CRS.

### Message :

```
* Install Apache modsecurity to guard webserver against web application attacks [HTTP-6643]
    - Related resources
      * Website: https://cisofy.com/lynis/controls/HTTP-6643/
```

### Solution :

Installation des prérequis :
```
sudo pacman -S --needed \
    apache \
    git \
    gcc \
    cmake \
    make \
    automake \
    autoconf \
    libtool \
    pcre2 \
    yajl \
    curl \
    lmdb \
    geoip \
    lua \
    pkgconf
```

Build et installation du moteur :
```
git clone --depth 1 https://github.com/owasp-modsecurity/ModSecurity

cd ModSecurity

git submodule init
git submodule update

sudo ./build.sh

sudo ./configure

# Si vous avez une erreur en rapport avec Mbed TLS :
git submodule update --init --recursive

sudo make -j$(nproc)

sudo make install
```

Build et installation du connecteur pour le serveur Apache :
```
git clone --depth 1 https://github.com/owasp-modsecurity/ModSecurity-apache

cd ModSecurity-apache

./autogen.sh

sudo ./configure \
    --with-apxs=/usr/bin/apxs \
    --with-libmodsecurity=/usr/local/modsecurity

sudo make -j$(nproc)

sudo make install
```

Configuration de modsecurity, dans le fichier ```/etc/httpd/conf/extra/modsecurity.conf``` :
```
LoadModule security3_module modules/mod_security3.so

<IfModule security3_module>
    modsecurity on
    modsecurity_rules_file /etc/httpd/modsecurity/modsecurity.conf
</IfModule>
```

Configuration du serveur Apache, pour inclure la configuration de modsecurity, dans le fichier ```/etc/httpd/conf/httpd.conf``` :
```
...

Include conf/extra/modsecurity.conf
```

Création du répertoire qui va contenir la configuration principale de modsecurity et les règles :
```
sudo mkdir -p /etc/httpd/modsecurity
```

Copie des fichiers de configuration :
```
sudo cp \
~/Téléchargements/modsec/ModSecurity/modsecurity.conf-recommended \
/etc/httpd/modsecurity/modsecurity.conf

sudo cp ~/Téléchargements/modsec/ModSecurity/unicode.mapping \
    /etc/httpd/modsecurity/unicode.mapping
```

Modification du fichier ```/etc/httpd/modsecurity/modsecurity.conf``` :
```
sudo sed -i \
's/SecRuleEngine DetectionOnly/SecRuleEngine On/' \
/etc/httpd/modsecurity/modsecurity.conf

# Puis dans le fichier, il faut ajouter :
SecAuditEngine RelevantOnly
SecAuditLog /var/log/httpd/modsec_audit.log
```

Enfin, on vient créer le fichier de logs :
```
sudo touch /var/log/httpd/modsec_audit.log
```

Comment nous l'avons dit précédemment, il n'y a aucune règle par défaut, nous installerons alors OWASP CRS qui permet d'en avoir.

Installation :
```
cd /etc/httpd

sudo git clone https://github.com/coreruleset/coreruleset.git crs

sudo -s

cd /etc/httpd/crs

cp crs-setup.conf.example crs-setup.conf
```

Il suffit ensuite d'inclure les fichiers dans la configuration principale de modsecurity, c'est-à-dire le fichier ```/etc/httpd/modsecurity/modsecurity.conf``` :
```
...

Include /etc/httpd/crs/crs-setup.conf
Include /etc/httpd/crs/rules/*.conf
```

Enfin, nous réactualisons le serveur Apache :
```
sudo httpd -t
```

> [!IMPORTANT]
> À chaque mise à jour, il faudra refaire le build et la configuration.
