# AUTH-9230 ([retour](../lynis.md))

Les « rounds » définissent le nombre d'itérations que va effectuer l'algorithme de hash, pour rendre ce dernier plus long et le mot de passe plus difficile à déchiffrer.

### Message :

```
* Configure password hashing rounds in /etc/login.defs [AUTH-9230]
    - Related resources
      * Article: Linux password security: hashing rounds: https://linux-audit.com/authentication/configure-the-minimum-password-length-on-linux-systems/
      * Website: https://cisofy.com/lynis/controls/AUTH-9230/
```

### Solution :

Dans un premier temps, il faut déterminer l'algorithme utilisé pour le hash des mots de passe. Pour cela, il suffit de regarder dans le fichier ```/etc/shadow```, puis sur une ligne représentant un utilisateur, il faut regarder la suite de caractères après le premier signe de dollar.

Par exemple, si vous voyez "y" c'est l'algorithme YesScript.

Puis pour modifier les rounds, nous avons deux possibilité :

\- Soit via le fichier ```/etc/login.defs``` :
```
# Pour YesScript :
YESCRYPT_COST_FACTOR n 
# (Avec n compris entre 1 et 11, en sachant que la valeur par défaut est 5.)
...
SHA_CRYPT_MIN_ROUNDS n 
# (en sachant que la valeur par défaut est 5000)
```

\- Soit via le fichier ```/etc/pam.d/system-auth``` :
```
password required pam_unix.so ... <algo> rounds=<valeur>
```

> [!NOTE]
> Dans mon cas, pour que la suggestion soit effacée de mon rapport Lynis, il fallait que je fasse les deux configurations.
