# KRNL-6000 ([retour](../lynis.md))

Il s'agit du même principe que pour [FILE-7524](./FILE-7524.md), sauf que cette fois-ci, il s'agit des valeurs pour les paramètres du Kernel.

### Message :

```
* One or more sysctl values differ from the scan profile and could be tweaked [KRNL-6000]
    - Solution : Change sysctl value or disable test (skip-test=KRNL-6000:<sysctl-key>)
    - Related resources
      * Article: Linux hardening with sysctl settings: https://linux-audit.com/linux-hardening-with-sysctl/
      * Article: Overview of sysctl options and values: https://linux-audit.com/kernel/sysctl/
      * Website: https://cisofy.com/lynis/controls/KRNL-6000/
```

### Solution :

Pour lister les paramètres du Kernel et les valeurs attendues :
```
sudo lynis show details KRNL-6000
```

Puis il suffit de modifier les valeurs comme, par exemple, dans le fichier ```/etc/sysctl.d/99-security.conf``` :
```
...

# Hardening Lynis

dev.tty.ldisc_autoload = 0
fs.protected_fifos = 2
fs.protected_regular = 2
net.ipv4.conf.all.log_martians = 1
net.ipv4.conf.default.log_martians = 1
kernel.sysrq = 0
fs.suid_dumpable = 0
```

Puis de réactualiser les valeurs avec sysctl :
```
sudo sysctl --system
```

Dans mon cas, j'ai dû créer un service (```/etc/systemd/system/log-martians.service```) pour changer les valeurs du paramètre « log_martians », car elles se remettaient avec d'autres valeurs, bien que ce paramètre fût précisé dans le fichier précédent :
```
[Unit]
Description=Apply log_martians network hardening
After=NetworkManager-wait-online.service
Wants=NetworkManager-wait-online.service

[Service]
Type=oneshot
ExecStart=/usr/bin/sysctl -w net.ipv4.conf.all.log_martians=1
ExecStart=/usr/bin/sysctl -w net.ipv4.conf.default.log_martians=1
ExecStart=/usr/bin/sysctl -w net.ipv4.conf.wlp1s0.log_martians=1
RemainAfterExit=yes

[Install]
WantedBy=multi-user.target
```

Actualisation de la liste des services présents sur le système, activation et lancement du service précédent :
```
sudo systemctl daemon-reload
sudo systemctl enable --now log-martians.service
```
